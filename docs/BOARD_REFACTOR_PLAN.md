# Board 重构与体积优化计划

## 当前基线（2026-09-15）

- 整个工作目录约 352 MB：`node_modules` 约 258 MB、`.git` 约 85 MB；这两项分别属于可重建依赖和历史记录，不用源码重构数字混在一起。
- 受版本控制的项目文件约 4.8 MB；其中 `components` 约 1.6 MB、`utils` 约 708 KB。
- `components` 与 `utils` 中约有 205 个源码文件、约 5 万行 TypeScript。
- 生产输出约 4.1 MB；作为发布产物的辅助指标，不再代表本计划所说的“整个代码包体积”。
- `components/BoardView.tsx`：本批由 4518 行降至 4460 行。
- Board 视图产物：本批由约 96.5 KB / gzip 31.2 KB 降至约 93.1 KB / gzip 29.4 KB。
- Board 当前会同步关联 NoteEditor（gzip 约 232.3 KB）；这是为了保证长按新建、落位动画和编辑器开启之间的节奏稳定，应继续在进入 Board 时准备好。Board 便签使用完整 Markdown 渲染器（gzip 约 26.2 KB），同样属于应保留的核心展示能力。
- HEIC 转换器约 1.35 MB，gzip 后约 341 KB；目前已按需加载，应继续保持，不得进入普通 Board 首载链路。
- `dist` 当前总体积约 4.1 MB。该数字包含所有按需视图与资源，只作为全局观察值，不作为 Board 单项验收值。

> 构建文件名带内容哈希，每次构建会变化；计划只比较体积和依赖关系，不固定文件名。

## 总体进度

整体约完成 40%。第一阶段“交互状态收口”已经完成，本批完成了不影响即时交互的导入链路瘦身；主体拆分和大数据量渲染优化仍待进行。

### 已完成

- 用统一交互状态机收口画布平移、框选、Frame 绘制/拖动/缩放和图片缩放，减少互相抢占。
- 统一 Pointer Capture，避免移动端拖动中断和子元素 `pointerup` 竞态。
- 抽离 Board 坐标换算、便签拖动、排布与 Frame 控件。
- 将批量时间、浏览筛选、多选工具栏、顶部编辑工具等 UI 从主文件拆出。
- HEIC 转换保持动态加载，未进入普通首载包。
- EXIF 改为照片导入时动态加载，不再随 Board 或 Mapping 视图提前下载。
- Board、Mapping 与通用媒体入口共用一套 EXIF GPS 读取和 HEIC 转换实现。
- 删除 MapView 中未使用的 EXIF 静态依赖，以及图片导入中失效的参数和中间变量。
- 删除未使用的 `cytoscape-cose-bilkent` 及冗余的顶层图布局依赖声明；保留实际使用的 `cytoscape-fcose` 依赖链。
- Tailwind 只保留 Vite 构建链路，移除重复的 PostCSS 配置、`@tailwindcss/postcss` 和未使用的 `autoprefixer`；Vite 插件归入开发依赖。

### 尚未完成

- NoteEditor 随 Board 一起进入依赖链会增加体积，但可换取第一次打开也无等待的稳定交互，本轮不拆成打开时加载。
- Board 的 Markdown 渲染属于核心能力，需要保留；后续只检查能否与其他视图复用同一份依赖，不降级显示效果。
- 主组件仍承担导入、媒体、选择、渲染、工具栏和编辑器桥接等过多职责。
- 大量便签时还没有视口裁剪；无关卡片也会参与 React 渲染与更新。
- 尚未建立稳定的 bundle 预算与回归检查。

## 优先目标：缩减项目体积

这里的“体积”优先指整个项目代码包，而不只是浏览器首次下载的 chunk。顺序是：减少重复源码与无效实现、清理无用依赖和重复构建链路、避免提交可重复生成的冗余产物；运行时 bundle 是次级指标。

本轮采用温和目标：不删除实际能力，不以牺牲 Markdown、NoteEditor、动画或交互完整性换取数字下降，也不以机械拆文件代替真正瘦身。

### 体积预算

1. 先删除可以证明无引用的依赖、失效参数、重复工具函数和重复构建配置。
2. 同类业务只保留一个基础实现；Board、Mapping 的差异通过薄适配层表达，不复制整段导入、媒体或窗口逻辑。
3. `node_modules` 和 `.git` 单独观察：前者靠依赖清单减重，后者不通过危险的历史重写处理。
4. NoteEditor、Markdown 与基础编辑能力在进入 Board 时准备好，避免第一次使用产生不可预测延迟。
5. EXIF、HEIC 等低频重能力继续按触发加载，但不把所有小组件都碎片化拆包。
6. `BoardView.tsx` 先以降至约 3500 行为观察目标，不设激进的最终行数指标；只抽离稳定、职责明确的领域逻辑。

## 执行顺序

### P0：建立可重复基线

- 记录受控文件总量、主要目录大小、源码行数、直接依赖数量和可重建生成文件。
- 同时记录 Board 首开、打开 NoteEditor、导入普通图片、导入 HEIC 四条加载链路，作为运行时辅助指标。
- 验收：每批改动都能回答“代码包删除了什么重复项，以及是否改变用户能力”。

### P1：先做不影响即时交互的瘦身

1. NoteEditor 保持随 Board 提前准备，不改为点击后才加载；其首次打开体验优先于这部分体积收益。
2. 保留 Board 卡片的完整 Markdown 渲染，检查它与其他预览是否使用同一依赖产物，避免重复打包。
3. 将 `exifr` 改为图片导入时动态加载。（已完成）
4. 把 Board 对根级 `utils` 聚合模块的引用改为直接模块引用，避免重型导出意外进入依赖链。
5. 再评估数据导入预览、媒体详情和裁剪等不会阻塞核心操作的低频能力；收益很小或会造成可感知等待的组件不拆包。
6. 删除重复的 Tailwind PostCSS 构建链路和未使用依赖；构建工具统一放入开发依赖。（已完成）

### P2：按领域继续拆主组件

- `BoardCanvasLayer`：只负责画布、Frame、连线和便签的渲染。
- `useBoardSelection`：单选、多选、框选与选择后的批量操作。
- `useBoardViewport`：平移、缩放、定位、视图持久化与坐标换算。
- `useBoardImportController`：JSON/CSV/图片导入和错误状态。
- `useBoardEditorBridge`：新建/删除动画、编辑器开启关闭、草稿与持久化衔接。
- 原则：状态放到最接近使用位置，跨层只传稳定命令和必要数据。

### P3：大画布性能

- 便签组件 `memo` 化，避免缩放/工具栏状态导致所有便签重渲染。
- 画布变换优先使用 DOM/CSS transform 与 `requestAnimationFrame`，不在每个 pointer move 写入大范围 React 状态。
- 数据量达到阈值后启用带缓冲区的视口裁剪；选中、拖动和动画中的对象始终保留。
- 将昂贵的边界、筛选和碰撞计算建立索引或缓存，避免每帧全量扫描。

### P4：删除重复与遗留代码

- 合并 Board 与通用图片导入中重复的 EXIF、HEIC、压缩和尺寸检测流程。
- 删除旧手势状态、未使用回调、重复窗口壳与已经失效的兼容分支。
- 检查仅被单处使用且无必要的依赖，确认可替代后再移除 package。

## 每批验收

- 生产构建通过。
- Board 浏览、长按新建、拖动、框选、Frame、图片导入、编辑器开关与删除动画不回退。
- 记录 Board 首开和编辑器打开后的 gzip 变化。
- 记录 `BoardView.tsx` 行数，但行数不得凌驾于行为清晰度和体积收益。
- 移动端 Pointer Capture、滚动阻止和长按 release 行为单独复核。

## 下一批建议范围

只做 P0 + P1，不同时启动大规模渲染层重写。NoteEditor 与 Markdown 保持进入 Board 时可立即使用，先处理未触发的 EXIF、重复依赖和低频非核心能力；确认交互无回退后，再进入 P2。
